# 正则表达式学习工具 · 设计方案

> 定位：不是 Regex Tester，而是一条「概念 → 例子 → 动手改 → 实时看 → 练习 → 错因 → 下一节」的学习流水线。
> 技术栈：Vue 3 + TypeScript + Vite + Element Plus，纯前端（数据落 localStorage），`npm install && npm run dev` 即可跑。

---

## 0. 设计原则（优先级排序）

1. **看得见的因果**：任何一次正则改动，右侧高亮、匹配列表、逐字符解释必须同时刷新。学习靠"我改了一个字符，结果为什么变了"。
2. **不直接给答案**：错误 → 诊断 → 三级提示 → 才给标准答案。提示是递进的，第 1 条不点破语法。
3. **解释必须拆到 token 粒度**：`^\d{3}-\d{4}$` 拆成 6 行，不能一句话带过。
4. **题面必须可随机**：知识点固定，文本随机，防止背答案。
5. **少即多**：v1 不做用户系统、不做后端、不做社区。离线可用的单页应用。

### 1.2 学习闭环（每个知识点的固定动线）

```
概念卡（一句话本质 + 类比）
  → 最小例子（1 个，只演示这一件事）
  → 对比例子（2~3 个，只改一个变量）
  → 右侧实验区（预填本节示例，用户自己改）
  → 本节练习（1~3 题，含三级提示）
  → 判定 + 错因分析
  → 详细解析（答案怎么来的、为什么你的不行）
  → 标记本节已学，推进进度
```

### 1.3 关键交互约定

- **输入即算**：文本框 / 正则在 `input` 事件后 120ms 防抖重算；非法正则不弹窗，在输入框下方给红色内联提示，保留上一次高亮（灰化）。
- **匹配高亮**：命中的片段加底色，交替两种底色区分相邻匹配；0 宽匹配（如 `^`、`(?=x)`）用竖线标记，避免"明明匹配了却看不见"。
- **示例可一键送入实验室**：每个例子右上角有「在实验室打开」，携带 text/pattern/flags 跳转。
- **答案比对不看写得好不好，只看结果对不对**：判定标准是"在题面文本上产出的匹配结果 = 期望结果"，不做正则字面比对（否则 `[0-9]+` 会被判错）。
- **不允许"写死答案"**：若用户正则不含任何元字符且等于某个期望匹配，提示"你匹配的是这段具体文本，题目要求对同类文本都成立"。

## 3. 学习课程体系

11 章 / 45 节 / 50 道练习，每节固定含：本质句、要点、2~3 例、1~3 题。
（实际交付：91 个示例、50 道练习、13 个实战案例，全部由 `npm run verify` 断言。）

| 章 | 节 | 核心示例 | 练习考点 |
|---|---|---|---|
| 01 正则基础 | 什么是正则表达式 | 一段日志里为什么能"一眼定位"订单号 | 判断哪些是元字符 |
| | 普通字符 | `cat` → `cat` | 字面量匹配 |
| | `.` | `a.c` 匹配 `abc`/`a c`，不匹配 `ac` | 任意字符（不含换行） |
| | `\d` / `\D` | `abc123xyz` → `123` | 提取数字 / 提取非数字 |
| | `\w` / `\W` | `user_id-42` | 单词字符（字母数字下划线） |
| | `\s` / `\S` | 多空格文本 | 空白字符 |
| 02 字符集合 | `[]` | `[abc]+` vs `abc` | 集合是"任选一个" |
| | `[abc]` / `[a-z]` / `[A-Z]` / `[0-9]` / `[a-zA-Z]` | `[0-9]+` 与 `\d+` 等价性 | 区间写法、连字符位置 |
| | `[^abc]` / `[^0-9]` | `[^0-9]+` 取非数字片段 | 取反集合、`^` 在集合内是取反 |
| 03 数量限定符 | `*` / `+` / `?` | `\d+` vs `\d*` vs `\d?` 同文本三结果 | 0 次与 1 次的区别 |
| | `{n}` / `{n,m}` / `{n,}` | `\d{3}` 只能吃 3 位 | 上下界、超出部分如何切分 |
| | 对比专题 | `\d+` / `\d*` / `\d?` 并排对比 | 为什么 `+` 和 `*` 不一样 |
| 04 边界 | `^` / `$` | `^abc` / `abc$` / `^abc$` | 部分匹配 vs 整串 |
| | 多行 `m` flag | 逐行日志 | `^` 在 `m` 下的含义 |
| 05 分组 | `()` | `(ab)+` vs `ab+` | 分组改变量词作用域 |
| | `(?:)` | `(?:ab)+` 不占捕获号 | 捕获组编号怎么数 |
| 06 或运算 | `\|` | `java\|python` 与 `(java\|python)开发` | 优先级陷阱：`^a\|b$` |
| 07 转义 | `\.` `\+` `\*` `\?` `\(` `\)` `\[` `\]` | 匹配 `3.14` 里的点 | 元字符清单 |
| | 特殊字符专题 | `$` `^` `\|` `{` `}` `\\` | Java 双层转义预告 |
| 08 贪婪/非贪婪 | `.*` vs `.*?` | `<a>123</a><a>456</a>` | 为什么 `.*?` 只吃到最近的 `</a>` |
| | `+?` / `??` / `{n,m}?` | `".*?"` 提取引号内容 | 懒惰量词 |
| 09 捕获组 | `group(0/1/2)` | `(SO)(\d+)` → 3 组 | 分组编号、嵌套编号顺序 |
| 10 前瞻后顾 | `(?=)` `(?!)` `(?<=)` `(?<!)` | `\d+(?=元)` 命中 100 不命中 100美元 | 零宽断言不消耗字符 |
| 11 Java 专题 | Pattern/Matcher `find()` vs `matches()` | `SO\d+` 在长文本中 find 成功、matches 失败 | 两个 API 的语义差别 |
| | `group(n)` / `replaceAll` / `split` | 订单号提取、脱敏、按分隔符切 | `$1` 反向引用 |
| | 双层转义 | 正则 `\d+` → Java `"\\d+"` | 为什么是两层 |

> 每章末有"章末小结"暗卡：把本章元字符列成一张表，点击可跳实验室试。

## 4. 数据结构设计

### 4.1 课程（静态，TS 常量）

```ts
interface Lesson {
  id: string                 // 'basics-digit'
  title: string
  essence: string            // 一句话本质
  points: string[]           // 3~5 条要点
  examples: RegexExample[]   // 2~3 个
  pitfalls?: { wrong: string; why: string }[]
  exercises: Exercise[]
}
interface RegexExample {
  title?: string             // '只匹配数字'
  text: string
  pattern: string
  flags?: string
  goal?: string              // 这个例子想让你看到什么
  expect?: string[]          // 期望完整匹配（构建时断言，防课程写错）
  groups?: (string | null)[]
}
interface Exercise {
  id: string
  level: 1 | 2 | 3 | 4 | 5
  prompt: string
  text: string
  flags?: string
  mode?: 'matches' | 'groups' | 'count'
  expect: string[]           // matches: 完整匹配数组；groups: 首个匹配的 group1..n；count: 长度
  answer: string             // 标准答案
  accept?: string[]          // 其它可接受写法
  hints: string[]            // 恰好 3 条，递进
  explain: string            // 详细解析
  knowledge: string[]        // ['\\d', '+'] 用于搜索与统计
}
```

### 4.2 进度与错题（localStorage）

```ts
interface ProgressState {
  version: 1
  lessons: Record<string, {
    learned: boolean
    attempts: number
    correct: number
    streak: number            // 本节连续答对
    bestStreak: number
    wrong: number
    lastAt: number
  }>
  stats: { attempts: number; correct: number; streak: number; bestStreak: number }
  last: { lessonId: string; title: string; at: number } | null
  mistakes: Mistake[]
}
interface Mistake {
  id: string                  // `${exerciseId}`，同题合并
  exerciseId: string
  lessonId: string
  lessonTitle: string
  prompt: string
  text: string
  level: number
  myPattern: string           // 最近一次错误写法
  answer: string
  reason: string              // 生成的错因
  knowledge: string[]
  count: number
  fixed: boolean
  at: number
}
```

- 单一 store（`reactive` + `watch` 深监听 → `localStorage` 防抖写），key `regex-lab/progress/v1`。
- 掌握度 = `correct/attempts` 加权，配合 `learned` 给下限：`learned ? max(40, rate*100) : min(rate*100, 40)`。

## 6. 正则解析方案（工具的硬核部分）

### 6.1 两层

1. **匹配层**：交给浏览器 `RegExp`，不自己写引擎（正确性优先）。统一 `compile(pattern, flags)`：去掉用户 `g` 后强制加 `g`；`exec` 循环收集 `{value,index,end,groups,named}`；空匹配 `lastIndex++` 防死循环；上限 1000 次 / 文本 20k 字符；`try/catch` 转成人话错误（如"括号未闭合""量词没有作用对象"）。
2. **解析层**：自己写一个**小而完整的正则词法+语法分析器**，产出 AST，再降维成 token 行。这一层只服务"解释"，不参与匹配。

### 6.2 解析器

```
parseAlternation := parseSequence ('|' parseSequence)*
parseSequence    := (parseAtom Quantifier?)*
parseAtom        := '(' Group | '[' CharClass | '\' Escape | '.' | '^' | '$' | Literal
Quantifier       := ('*'|'+'|'?'|'{n[,m]}') ('?'|'+')?
```

- 分组识别：`(`、`(?:`、`(?=`、`(?!`、`(?<=`、`(?<!`、`(?<name>`。
- 字符集：支持 `^` 取反、`a-z` 区间、内部 `\d` `\w` `\s` `\\` `\]`。
- 量词只在合法位置吸附前一个 atom，孤立的 `*` 标记为"这里 `*` 会被当普通字符/报错"。
- 输出 `TokenRow[]`：`{ raw, name, detail, depth, kind }`。

### 6.3 解释生成

token 表（逐行，左列是**正则原文**，右列是中文）：

| raw | name | detail |
|---|---|---|
| `^` | 字符串开头 | 要求从这里开始匹配 |
| `\d` | 数字字符 | 匹配任意一个 0-9 |
| `{3}` | 数量限定符 | 前面的数字连续出现 3 次 |
| `-` | 普通字符 | 就是字面量 `-` |
| `$` | 字符串结尾 | 要求到这里结束，后面不能再有字符 |

再加一段**组合解释**（不是 token 拼接，而是按结构重写）：

`^\d{3}-\d{4}$` → "整段文本必须严格是：3 个数字 + 一个 `-` + 4 个数字，不能多也不能少。"
规则：遇到 `^`/`$` 判定"整串/前缀/后缀"语气；序列用 `，接着` 连接；`|` 转成"或者"；分组转成"（…）整体"；`(?=x)` 转成"并且后面必须紧跟 x（但不消耗）"。

### 6.4 边界情况

- 非法正则：解析器尽量"容错解释"（未知 token 标灰 + 提示），匹配层给红色错误，二者不互相阻塞。
- 不支持（v1 明确提示"暂不解释，仍可匹配"）：反向引用 `\1`、命名反向引用 `\k<name>`、`\p{...}` Unicode 属性、条件组、`(?x)` 等内联 flag。匹配交给浏览器照样能跑。

## 7. 练习题生成方案

### 7.1 两类题

| 类型 | 来源 | 判定 |
|---|---|---|
| 固定题 | 课程 `Exercise[]`，逐节配套 | 编译用户正则 → 在题面文本上求值 → 与 `expect` 对比 |
| 随机题 | `core/generate.ts` 中的生成器 | 同上（生成时同步产出 `expect`，天然自洽） |

### 7.2 随机生成器（知识点固定，数据随机）

```ts
type Generator = {
  id: string; name: string; level: 1|2|3|4|5; knowledge: string[]
  build(rng: () => number): Exercise
}
```

`rng = mulberry32(seed)`，seed 取 `Date.now()`，同一轮 10 题不重复。
已实现：`digit-extract`（提取数字）、`digit-range`（3~5 位）、`paren-extract`（括号内容）、`lookahead-price`（元/美元）、`order-no`（订单号）、`log-field`（userId/action）、`url-parts`、`ip-port`、`email`、`phone-mask`、`date-normalize`、`java-exception`、`sql-table`…

每个 `build` 里**先造数据、再算期望**（而不是写死期望），例如生成 `n` 个 3~5 位数字和若干个 2 位/6 位干扰项，`expect` 直接取那些合法项，保证永不出错。

### 7.3 判定与诊断

```
run(userPattern) → { ok, error, matches }
归一化：matches 模式取 value[]；groups 模式取首个匹配的 group1..n；count 取 length
正确 ⟺ 归一化结果 === expect
```

错误归因（按顺序命中第一条）：

| 现象 | 归因文案 |
|---|---|
| 正则有语法错误 | 指出错误位置，提示检查括号/方括号/量词 |
| 0 个匹配 | "你的正则在这段文本里没找到任何东西" + 领域提示 |
| 匹配数多、每段更短，且都是期望值的子串 | "你把一个整体拆成了 N 段，缺数量限定符"（`\d` vs `\d+`） |
| 匹配数多且更长/覆盖了非目标 | "匹配过头了，'子串也能匹配' 不等于 '只匹配想要的'"（`\d+` vs `(?<!\d)\d{3}(?!\d)`） |
| 匹配数少 | "漏匹配，看看目标之间的分隔符/大小写/空白" |
| 数量相同但内容不同 | 并排 diff 具体差异项 |
| 正则无元字符且等于文本片段 | "写死了具体文本，题目要求同类文本通用" |

三级提示：第 1 条说方向（"你需要匹配连续出现的数字"），第 2 条点符号（"考虑 `\d`"），第 3 条给结构（"还需要一个量词，因为数字是连续多个"）。三条用完仍错 → 显示标准答案 + 详细解析。

## 8. 错题记录方案

- **触发**：`ExerciseCard` 判定失败时调 `store.recordMistake(exercise, userPattern, reason)`，同一 `exerciseId` 只累加 `count` 并覆盖 `myPattern/reason`。
- **内容**：题目原文 + 我的正则 + 正确答案 + 错误原因（第 7.3 的归因）+ 知识点标签 + 错误次数 + 时间。
- **复习**：错题本"重练"复用 `ExerciseCard`，复用同一判定逻辑；答对后 `fixed = true`（保留记录，显示"已订正 ✓"），并给该知识点 +1 正确。
- **清理**：只允许手动删除单条；不做自动清理（错题是资产）。
- **统计联动**：错题数计入进度页；"薄弱知识点"= 错题 `knowledge` 词频 Top 5，点击 → 搜索弹窗定位。

## 11. 风险与取舍

| 风险 | 处理 |
|---|---|
| 浏览器 `RegExp` 与 Java `Pattern` 行为差异 | 课程中显式标注差异点（`\d` 在 Java 默认只匹配 ASCII、`matches()` 需整串匹配） |
| 灾难性回溯卡死页面 | 文本 20k / 匹配 1000 次上限；量词嵌套时在 UI 提示"可能回溯很慢" |
| 答案判定"结果对但写法烂" | 只判结果；另给"写法建议"（如 `[0-9]` ≈ `\d`），不扣分 |
| 课程内容出错 | 每个示例/练习都带 `expect`，`scripts/verify-curriculum.mjs` 用 esbuild 打包后逐条断言，接 CI 前先手动跑 |
