## 修复：`\d*` 在高亮区"乱码"

- 现象：实验室里输入 `\d*`，高亮文本变成 `¦a¦ab¦abc123¦d¦de¦def456¦`。
- 根因（两层）：
  1. **游标不推进**：`\d*` / `\d?` 在每个不能匹配的位置产生长度 0 的空匹配。
     切片循环里空匹配分支没有 `cursor = m.index`，后续每段都从同一个旧游标 `slice`，
     文本被反复累加 —— 这才是"乱码"。
  2. **标记占位**：零宽 `<span class="zw">` 里塞了一个 `|` 字符，
     `width:0` 让它不占布局但字符仍溢出绘制，竖线插在每个字符间隙，字看起来被撕开。
- 修复：
  - 切片逻辑**收敛成唯一实现** `core/regex.ts#toSegments`（原先 `HighlightedText.vue`
    和 `toSegments` 各写一份，只改一处就会分叉），组件只负责渲染。
  - 空匹配分支也推进游标：`if (m.index > cursor) cursor = m.index`。
  - 去掉 `|` 文本，标记改用 `::after` 画 2×3px 小刻度，`.zw { width:0; height:0 }` 不参与行高。
  - `MatchList` 把连续 ≥3 个空匹配折叠成一行（"N 处连续空匹配 @a–b"，可点开），
    否则 `\d*` 能刷 27 行"空匹配"把真实匹配挤出视野。
  - 零宽 ≥3 时高亮区下方补一句解释："量词允许零次时每个位置都会匹配一次但不消耗字符，是正确结果"。
- 自检升级：`verify` 的断言改用产品自身的 `run()`，并新增「片段拼回去必须等于原文」断言
  （含 `\d*`/`\d?`/`^`/`$`/`(?=a)`/`\b`/空正则等 13 个零宽回归用例），断言数 163 → 330。
- 教训：**同一段逻辑在两个文件里各写一遍，是这类 bug 的温床**；能收敛成一个纯函数就收敛。

## 修复：判分层的空匹配"乱码"（10-27）

- 现象：练习题输入 `[abc]*`，结果区列出 5 个 `∅`，错因写「你多匹配到 「」、「」、「」、「a」」。
- 根因：判分把**空匹配当成普通结果项**参与数量比较和展示，空串被塞进引号就成了 `「」`。
- 决策：**空匹配仍参与判定**（否则用 `*` 提取内容会被误判为对，违背教学意图），
  但**单独计数、不混进结果项**。
  - `JudgeResult` 新增 `actualEmpty`；`analysisOf` 内部一律用 `content = actual.filter(v => v !== '')` 做比较。
  - 新增分支「内容全对、只是多了空匹配」→ 直接建议把 `*` / `?` 换成 `+`。
  - `extra` 与 `missing` 同时存在时改说「形状不对」（原来说"匹配过头"，对 `ab+` 得到 `ab/abb` 是误导）。
  - `ExerciseCard`：头部「你的结果 N 项 + M 个空匹配 / 预期 K 项」，实际行末尾一个灰色虚线 chip「+M 空匹配」。
  - `ExampleCard`：chip 里的 `∅` 改成「空」+ 虚线灰底；计数行写「匹配到 N 处（另有 M 处空匹配）」。
  - **`groups` 模式的空串是空捕获组，属于有效项，不能过滤**（`actualContent` 里按 mode 分支）。
- 自检：断言数 392，新增两组——
  1) 50 道题的标准答案（含 accept）必须 `judge()` 判对；
  2) 判分回归 `[abc]*`/`ab*c`/`[abc]+`/`ab+`/`a.c`/`abc*`，
     并断言**错因里不允许出现 `「」`**、有空匹配就必须在错因里解释。
- 注意：脚本注释里写 `/[abc]*/` 会因为其中的 `*/` 提前结束块注释，注释里别带完整正则字面量。
