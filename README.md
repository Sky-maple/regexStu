# 正则实验室 · Regex Learning Lab

不是又一个在线 Regex Tester，而是一条**能真正学完**的路径：

> 概念 → 最小例子 → 你改一个字符 → 立刻看到匹配结果 → 做一道题 → 看错因 → 下一节

纯前端（Vue 3 + TypeScript + Vite + Element Plus），数据存 localStorage，不需要后端。

---

## 快速开始

```bash
npm install
npm run dev      # http://127.0.0.1:5173
```

生产构建 / 预览：

```bash
npm run build
npm run preview
```

课程数据自检（推荐改完课程内容后跑一次）：

```bash
npm run verify
```

它会把所有示例和练习题的标准答案，在题面文本上真实执行一遍，
断言「期望匹配」与「实际匹配」完全一致 —— 防止课程里写错一个字符把你教歪。

## 核心设计（为什么它不只是个测试器）

### 1. 逐字符拆解

输入 `^\d{3}-\d{4}$`，工具会自己解析出 AST，再拆成：

| 片段 | 含义 | 说明 |
|---|---|---|
| `^` | 字符串开头 | 要求从这里开始匹配 |
| `\d` | 数字字符 | 匹配任意一个 0-9 的数字 |
| `{3}` | 数量限定符 | 前面的元素必须恰好连续出现 3 次 |
| `-` | 普通字符 | 只能匹配字符「-」本身 |
| `\d` | 数字字符 | … |
| `{4}` | 数量限定符 | … |
| `$` | 字符串结尾 | 要求到这里结束 |

外加一句**组合解释**（按结构重写，不是 token 拼接）：
「整段文本必须严格是：3 个数字，接着「-」，接着 4 个数字。多一个字符、少一个字符都不行。」

实现：`src/core/parser.ts`（手写解析器）+ `src/core/explain.ts`（token 表 + 组合语义）。

### 2. 判分只看结果，不看写法

`[0-9]+` 和 `\d+` 都会判对。判分器把用户正则跑在题面文本上，比较**匹配结果**；写死具体文本会被单独抓出来提示。

### 3. 错因分析（不是一句"错误"）

- 匹配到一堆单个数字 → 「你把一个整体拆成了 6 段，检查数量限定符」
- 匹配过多 → 「匹配过头了，多匹配到 xxx」
- 完全没匹配 → 「一个都没找到，可能是字符类型/边界/大小写卡住了」
- 正则有语法错误 → 翻成人话（括号未闭合、量词没有作用对象…）

### 4. 三级提示

第 1 条说方向，第 2 条点符号，第 3 条给结构。三条用完 / 试了 3 次，才允许看标准答案。

### 5. 随机题「先造数据、再算期望」

`src/core/generate.ts` 里 13 个生成器，先随机生成文本、同时算出标准答案，所以答案永远自洽，
同一考点每次数据都不同 —— 背答案没用。

## 目录结构

```
src/
├─ core/            # 纯函数：匹配 / 解析 / 解释 / 判分 / 出题
│  ├─ regex.ts      # 编译、执行、高亮切片（上限保护）
│  ├─ parser.ts     # 正则 → AST（分组、字符集、量词、断言、错误）
│  ├─ explain.ts    # AST → token 表 + 组合解释
│  ├─ evaluate.ts   # 判分 + 错因归因
│  └─ generate.ts   # 随机题生成器（mulberry32）
├─ data/
│  ├─ curriculum/   # 11 章课程（按阶段拆文件）
│  ├─ cases.ts      # 实战案例
│  ├─ samples.ts    # 20 类示例文本
│  └─ glossary.ts   # 知识点词条（支持 lookbehind 等英文搜索）
├─ stores/progress.ts  # 进度 / 错题 / 统计（localStorage）
├─ components/      # HighlightedText / TokenTable / MatchList / ExerciseCard / MiniLab …
└─ views/           # 8 个页面
scripts/verify-curriculum.mjs  # 课程数据自检
```

## 已知边界

- 匹配用的是浏览器的 `RegExp`，不是 Java 的 `Pattern`。课程里刻意标注了两者差异（`\d` 的 ASCII 语义、`matches()` 与 `find()`、双层转义）。
- 解释器不覆盖：反向引用 `\1`、命名反向引用 `\k<name>`、`\p{...}`、条件组、内联 flag。这些仍可正常匹配，只是没有逐字符解释。
- 匹配上限：文本 20k 字符、单次最多 500 个匹配，避免灾难性回溯把页面卡死。
- 数据只在本机 localStorage，换浏览器不同步（这是纯前端版本的取舍）。
